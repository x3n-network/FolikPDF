# On-device document conversion

The styled Office engine accepts **DOCX** and **ODT** and uses platform APIs only: Foundation XML parsing, zlib decompression, ImageIO, CoreText, CoreGraphics, and PDFKit. It does not execute macros, resolve network resources, upload documents, or require an external conversion service.

## Pipeline

1. `OfficePackage` reads ZIP central-directory metadata in memory, validates names and payload bounds, and verifies each consumed part with CRC32. Stored and deflate entries are supported. Nothing is extracted into filesystem paths.
2. `OfficeXML` canonicalizes namespaces (including transitional/strict Word namespaces) into bounded trees. It rejects DTDs/entities and never resolves external resources.
3. `DOCXReader` follows package relationships to the main document and its styles, numbering, and image parts. `ODTReader` reads the package MIME type, manifest, content and styles. Each produces `OfficeDocument` blocks and detected compatibility notes.
4. `OfficePDFRenderer` lays out selectable text with CoreText. Paragraphs and table cells can continue across pages. Raster images are decoded one at a time with orientation correction. Horizontal table spans are honored; nested cell content is flattened in reading order with a warning.
5. `OfficeConversionView` displays the generated bytes in PDFKit and exposes compatibility notes. Saving passes those same bytes to the existing atomic, duplicate-safe library import path. Cancelling the preview creates no library document.

## Supported content

- Paragraph and character style inheritance; font family/size, bold, italic, underline, strikethrough, superscript/subscript and RGB text color.
- Headings, alignment, basic paragraph spacing/indentation and explicit page breaks.
- Decimal, alphabetic, Roman and bullet lists; DOCX level/start overrides and nested restarts; inherited ODT list styles and named/recent list continuation.
- Embedded raster images in body text and table cells, constrained to the printable area.
- Basic tables, source column proportions, horizontal column spans, and multi-page cell content. Very narrow columns are widened with a warning.
- Original page size and four page margins where valid declarations are available; the initial layout is used throughout.
- Text-box content in reading order; DOCX alternate representations select one supported branch or fallback.
- Referenced footnotes/endnotes collected after the main content.
- Interactive external HTTP(S) and email hyperlinks, including links in table cells. Links are never fetched during conversion.

## Known differences

This is not a replacement for an Office layout engine. Complex section layouts, text wrapping/cropping/transforms, theme fidelity, precise table sizing/borders, vertical merges, headers/footers, comments, live fields, charts, vector artwork and embedded objects are not faithfully reproduced. Detected omissions and simplifications appear in conversion notes; not every possible format extension can be detected. Unknown content must receive a warning rather than being silently presented as fully supported.

Fields use saved display text. Internal bookmarks and unsupported hyperlink schemes retain text without navigation. Tracked changes generally show current DOCX text without revision markup. Custom list formats and ODT multi-level labels are simplified. Notes move to the end instead of their original page; text boxes lose their original position and shape. Fonts absent from the device are substituted. Text viewers may infer columns from spaces in aligned/code output and reorder extracted text even when all visible text is present.

Encrypted documents, pre-Word-97 DOC, ZIP64/split archives, Google Docs URLs, spreadsheets and presentations are unsupported. Google Docs users can export DOCX.

## Legacy Word and Pages fallbacks

`CompoundDocument` reads bounded CFB version 3/4 FAT, DIFAT, mini-FAT and root-level stream entries. It checks stream bounds and rejects cyclic chains/directory graphs. It does not execute macros or inspect embedded storages. `LegacyDOCReader` reads the Word 97–2003 FIB, CLX and piece table to recover main-story text. Unicode and compressed pieces, paragraph/cell boundaries, explicit page breaks and saved field results are supported. Only the main story is recovered; rich formatting, images, headers/footers, notes, comments and text boxes are omitted. Tracked deletions may appear. Encrypted/obfuscated input fails. This mode is visibly labeled **Text recovery only** above the preview.

`PagesPDFReader` accepts an exact `QuickLook/Preview.pdf` entry in a Pages ZIP or directory package. Directory reads are coordinated with file providers, bounded, and reject symlink components. It validates the PDF and page bounds and preserves the saved PDF bytes exactly. JPEG thumbnails are never used as a document substitute. The visible **Saved Pages preview** notice explains that the preview may be outdated or incomplete. This is not an IWA/Pages layout parser: files without a usable PDF preview receive actionable instructions to export from Pages.

These paths improve recoverability, not full-fidelity Office compatibility. Full original layout still requires export from the source app.

## Resource limits

- Input package: 25 MB; at most 4,096 ZIP entries.
- Expanded package: 100 MB total; 20 MB per part.
- XML part: 8 MB; 100,000 nodes; depth 80.
- Document: 2 MB of UTF-8 text, 10,000 table cells, 50 MB of referenced image data.
- Tables: at most 20 logical columns and 2,000 rows per table.
- Rendered PDF: at most 500 pages and approximately 50 MB.

Limits cause a recoverable conversion error. Cancellation propagates to parsing/rendering; no partially generated document is imported.

## Validation

`LegacyConversionTests` covers macOS-textutil-generated binary Word fixtures, Unicode and long documents, explicit mixed-encoding pieces, field results, encryption, malformed piece tables, cyclic CFB chains, cancellation, Pages ZIP/directory preview extraction, symlink rejection and thumbnail-only failures. The Pages archives are synthetic extraction fixtures, not a corpus of Pages versions. The generator is `FolikTests/Fixtures/generate_legacy_fixtures.py`; it requires macOS textutil only for the independent Word samples. Copy `LegacyUnicode.doc` and `PagesSavedPreview.pages` to UI test fixtures when regenerating.

`OfficeCompatibilityTests` checks asymmetric margins, column proportions, inline formatting, numbering overrides/restarts/continuation, note and text-box preservation, PDF hyperlink hit areas, alternate-content fallback and malformed ODT repeat counts.

`OfficeEngineTests` exercises independently generated DOCX/ODT fixtures, style inheritance, numbering, images, merged cells, long table pagination, exact-preview saving, archive integrity, bounds, XML entities, cancellation and optional private documents. `FolikUITests` exercises preview, save and cancellation for both formats, retaining preview screenshots.

Synthetic fixtures are generated by `FolikTests/Fixtures/generate_office_fixtures.py` using python-docx, odfpy and Pillow in a temporary Python environment. Additional focused fixtures are generated with the standard-library-only `generate_office_compatibility.py`. They contain no user data. If regenerating, also copy `OfficePreview.docx` and `OfficePreview.odt` into `FolikUITests/Fixtures`.

The optional external-document test is disabled by default. To run it, supply `TEST_RUNNER_FOLIK_OFFICE_OUTPUT` to xcodebuild, pointing to a private temporary directory containing `UserReport.docx`, `UserText.txt`, and `expected.json` (an independently extracted array of expected text fragments). PDFKit can infer columns in space-aligned output; split such expectations at the column gaps rather than assuming one paragraph-wide extraction order. The test writes converted PDFs and a comparison report there. Never check private inputs or outputs into the repository.
